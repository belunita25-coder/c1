# Конструкторы промптов для интерактивных HTML-игр

Два самостоятельных инструмента. Общего кода у них нет — каждый файл открывается
и работает сам по себе.

| Файл | Для чего |
|---|---|
| `index.html` | **Игра из одной механики.** Быстрый вариант: выбрал механику, настроил, получил промпт. |
| `complex.html` | **Игра из нескольких этапов.** На каждом этапе своя механика, общие правила задаются один раз для всей игры. |

---

# Конструктор игры из одной механики — `index.html`

Учитель выбирает игровую механику, задаёт параметры урока, добавляет обратную связь
и вовлечение — конструктор собирает готовый промпт для нейросети.

## Как пользоваться

Откройте `index.html` — двойным щелчком с диска, без сервера и без интернета.
Или встройте на сайт: вся разметка лежит внутри `<main id="prompt-constructor-iy">`,
стили ограничены этим идентификатором и не влияют на остальную страницу.

## Главное правило интерфейса

**Везде можно выбрать готовый вариант или вписать свой.**

- В каждом выпадающем списке последний пункт — «✍️ Свой вариант». При его выборе
  появляется поле для произвольного текста.
- В каждом текстовом поле есть выпадающие примеры, но писать можно что угодно.

Сейчас в конструкторе 187 списков с 942 готовыми вариантами плюс 37 текстовых полей
с примерами — всего около 1240 подсказок, и каждую можно заменить своим текстом.

## Что внутри

| Что | Сколько |
|---|---|
| Игровые механики | 32 в 7 категориях |
| Блоки обратной связи | 14 |
| Блоки вовлечения | 14 |
| Стили оформления с готовым рецептом | 28 |
| Готовые наборы блоков | 8 |

Каждой механике доступно минимум 4 блока обратной связи и 5 блоков вовлечения.

### Стили оформления

У каждого из 28 стилей есть готовый рецепт: палитра, характер фона, вид карточек,
набор декора и характер шрифта. Рецепт подставляется в промпт, поэтому нейросеть
оформляет игру целиком, а не только перекрашивает кнопки. Свой стиль тоже можно
вписать — тогда в промпт уходит инструкция сначала продумать для него полную
визуальную систему.

## Возможности

- промпт пересобирается сам при любом изменении; есть и кнопка «Создать промпт»,
  если хочется собрать вручную;
- «Очистить промпт» очищает только поле с текстом, настройки остаются на месте;
- настройки сохраняются в браузере и восстанавливаются после перезагрузки;
- «Ссылка на сборку» — можно передать коллеге настроенный набор;
- готовые наборы блоков: быстрая проверка, обучающая игра, урок-квест, тренажёр,
  игра на класс;
- проверки перед выдачей: несогласованные числа, пустые обязательные поля,
  конфликтующие блоки;
- скачивание промпта в `.txt`;
- работает с клавиатуры, учитывает `prefers-reduced-motion`, адаптирован под телефон.

## Разработка

`index.html` собирается из фрагментов, чтобы данные не смешивались с логикой:

| Файл | Что там |
|---|---|
| `build/01-head.html` | стили |
| `build/02-body.html` | разметка |
| `build/03-mechanics.js` | 32 механики |
| `build/04-blocks.js` | обратная связь и вовлечение |
| `build/05-fields.js` | общие поля, стили и рецепты оформления, готовые наборы |
| `build/06-app.js` | состояние и рендер |
| `build/07-prompt.js` | сборка промпта и проверки |
| `build/08-events.js` | события и запуск |

Пересобрать и проверить:

```sh
sh build/build.sh
```

`index.html` коммитится в репозиторий — он и есть рабочий файл.

### Как добавить механику

Допишите объект в `build/03-mechanics.js` и запустите сборку. Формат поля:

| Ключ | Значение |
|---|---|
| `k` | ключ, совпадает с `{плейсхолдером}` в тексте промпта |
| `l` | подпись поля |
| `t` | тип: `sel` список, `txt` текст, `num` число |
| `o` | варианты для `sel` |
| `v` | значение по умолчанию |
| `ph` | подсказка внутри пустого поля — **в промпт не попадает** |
| `ex` | примеры для `txt`, выпадают при нажатии |
| `min` / `max` | границы для `num`, используются в проверках |

Пункт «✍️ Свой вариант» добавляется ко всем спискам автоматически — прописывать
его в данных не нужно.

### Проверки

`build/validate.mjs` — сверяет плейсхолдеры с полями, ссылки блоков на механики,
дубли ключей, покрытие механик блоками, наличие подсказок не в том поле,
наличие рецепта у каждого стиля.

`build/validate-prompts.mjs` — прогоняет все 56 блоков с пустыми и заполненными
значениями и ловит обрубки вида «Персонаж: .» в готовом промпте.

# Конструктор игры из нескольких этапов — `complex.html`

Игра, где каждый этап — своя механика: например, флэш-карточки для знакомства
с темой, затем сопоставление, затем бродилка на закрепление. Это одна игра
с общим счётом и одним финалом, а не три игры подряд.

## Что внутри

| Что | Сколько |
|---|---|
| Игровые механики | 32, любую можно поставить на несколько этапов |
| Правила для всей игры | 19 блоков |
| Реакция на этапе | 8 блоков |
| Стили оформления с рецептом | 130 в 15 группах |
| Готовые наборы правил | 7 |
| Этапов в игре | от 2 до 8 |

## Два уровня настройки

Это главное отличие от одиночного конструктора:

- **Правила для всей игры** (шаг 4) — баллы, жизни, подсказки, награды, сюжет,
  персонаж, соревнование, финальный экран. Задаются один раз и действуют на всех
  этапах. Раньше эти блоки предлагались на каждом этапе, и промпт мог требовать
  три разных финальных экрана в одной игре.
- **Реакция на этапе** (шаг 3) — сигнал «верно/неверно», выделение ответов,
  пояснения, анимация, переход «Дальше», блокировка, таймер. Настраиваются
  отдельно для каждого этапа.

## Настройки этапов не теряются

Каждый этап получает собственный внутренний номер, и значения полей хранятся
привязанными к нему, а не к позиции в списке. Поэтому:

- добавление и удаление этапов не сбрасывает уже заполненные настройки;
- кнопки «↑ Выше» и «↓ Ниже» переставляют этап вместе со всеми его значениями;
- одну и ту же механику можно поставить на несколько этапов — у каждого будут
  свои независимые настройки.

Кнопки «Скопировать с предыдущего» и «Применить ко всем» переносят выбранные
блоки и их настройки между этапами, чтобы не заполнять одно и то же вручную.

## Тексты механик переписаны под этапы

У каждой из 32 механик есть отдельный текст для роли этапа: без команды
«создай игру», без своего финального экрана и без кнопки «Играть снова» —
в многоэтапной игре они должны быть один раз, в самом конце. Промпт также
прямо запрещает нейросети делать отдельный финал после каждого этапа
и требует переносить счёт между этапами.

## Разработка

`complex.html` собирается из фрагментов `buildx/`, механики и блоки берутся
из `build/` — тех же файлов, что и у одиночного конструктора, но собираются
в отдельный самостоятельный HTML:

| Файл | Что там |
|---|---|
| `buildx/x01-head.html` | стили |
| `buildx/x02-body.html` | разметка семи шагов |
| `buildx/x03b-stage-prompts.js` | тексты 32 механик в роли этапа |
| `buildx/x05a-styles.js` | 130 стилей с рецептами |
| `buildx/x05b-fields.js` | уровни блоков, общие поля, наборы |
| `buildx/x06-app.js` | состояние этапов и отрисовка |
| `buildx/x07-prompt.js` | сборка промпта и проверки |
| `buildx/x08-events.js` | события, копирование настроек, кнопки |

```sh
sh buildx/build.sh
```

`buildx/validate.mjs` проверяет, что у всех механик есть этапный текст,
что в нём не осталось команды создать игру или своего финала, что плейсхолдеры
сходятся с полями, у каждого блока задан уровень, а у каждого стиля — рецепт.
